## 4. Tier 2 — deferred, and deliberately NOT allowlisted

The plan says a rejected golden is recorded in the allowlist. **That does not apply here, and writing the entries anyway would have been wrong.**

Tier 2's 14 are not *rejected on quality grounds* — they are **deferred by policy**, because adopting them would pin as the reference an emit that **demonstrably does not reproduce its NLP solution** (7 `mismatch`, 6 `skipped`, 1 `model_infeasible`). And since **no presolve golden is committed for any of them**, an allowlist entry would be **inert and misleading**: `discover_goldens()` only finds files that exist, so the entry records nothing while implying an exclusion that was never made.

**Verified:** zero Tier-2 models have a committed presolve golden. All 14 remain in the sweep via their **cold** goldens, which is unchanged and correct.

**The hazard this avoids is concrete:** pin a wrong-but-stable emit, and when someone later *fixes* it the gate reports drift — and the reflex is `make regen-goldens`, which is exactly the laundering path the leak gate exists to prevent.

## 5. `--min-scope` — derived, and from the right source

Raised **in the same commit that adds the goldens**, so the assertion cannot lag the corpus.

**It is derived from `git ls-files`, not from the filesystem, and that distinction is load-bearing.** `discover_goldens()` **globs `data/gamslib/mcp/`** — so a filesystem count is *the same quantity it starts from*, and asserting against it would compare a number to itself and always pass. **That is the self-certification defect this whole priority is about, reappearing inside its own guard.** `git ls-files` is independent: it counts what is **committed**, regardless of whether the raw corpus was provisioned — precisely the failure `--min-scope` exists to catch.

```yaml
MIN_SCOPE=$(git ls-files 'data/gamslib/mcp/*.gms' | wc -l | tr -d ' ')
test "$MIN_SCOPE" -gt 0 || { echo "ERROR: git ls-files found no goldens — the floor would be vacuous."; exit 1; }
python scripts/sprint_audit/check_golden_staleness.py --min-scope "$MIN_SCOPE" --json golden-staleness.json
```

The `-gt 0` guard matters: a derivation that silently yields `0` would make the floor vacuous, which is the same class of failure one level down.

## 9. Reproduction

```bash
# §2 — validate the method against an ALREADY-COMMITTED golden first
mkdir -p /tmp/d8/val && cd /tmp/d8/val
.venv/bin/python -m src.cli data/gamslib/raw/agreste.gms --nlp-presolve -o agreste_mcp_presolve.gms
diff agreste_mcp_presolve.gms data/gamslib/mcp/agreste_mcp_presolve.gms   # byte-identical

# §3 — determinism (zsh does NOT word-split unquoted vars; use an array)
t1=(catmix cpack etamac harker hhfair himmel16 irscge like lrgcge marco mathopt1
    mathopt4 maxmin mingamma moncge paperco qsambal sambal stdcge tforss weapons worst)
for seed in 0 1 42; do for m in $t1; do
  PYTHONHASHSEED=$seed .venv/bin/python -m src.cli data/gamslib/raw/$m.gms \
    --nlp-presolve -o /tmp/d8/s$seed/${m}_mcp_presolve.gms
done; done   # then compare hashes across seeds

# §5 — the two candidate sources for the floor
git ls-files 'data/gamslib/mcp/*.gms' | wc -l    # 192 — INDEPENDENT
ls data/gamslib/mcp/*.gms            | wc -l    # 192 — VACUOUS (what discover_goldens globs)
```
