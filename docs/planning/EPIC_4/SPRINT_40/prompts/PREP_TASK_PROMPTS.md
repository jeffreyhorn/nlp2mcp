**Purpose:** ready-to-paste execution prompts for the Sprint-40 preparation tasks defined in `docs/planning/EPIC_4/SPRINT_40/PREP_PLAN.md`. Paste one prompt per prep task. **Standing conventions (apply to every prompt below):**

- **Branch:** work on **`planning/sprint40-task<Z>`** where `<Z>` is the task number (e.g. Task 4 → `planning/sprint40-task4`), branched from **`main`**. ⚠ `PREP_PLAN.md`, `KNOWN_UNKNOWNS.md` and this file live on `planning/sprint40-prep` until it merges — **confirm they are on `main` before branching** (`git show main:docs/planning/EPIC_4/SPRINT_40/KNOWN_UNKNOWNS.md >/dev/null`). Never `git stash` to switch branches; `git show <ref>:<path>` is read-only (S39 retro §7.7).
- **Verify each associated Known Unknown**: in `docs/planning/EPIC_4/SPRINT_40/KNOWN_UNKNOWNS.md`, change the unknown's Verification Results line from `🔍 **Status:** INCOMPLETE` to `✅ **Status:** VERIFIED` or `❌ **Status:** WRONG` (with the correction) — or `🔶 **Status:** PARTIALLY WRONG` where only part holds — and add **Verified by**, **Date**, **Measured at** (the commit), **Findings**, **Evidence** (the commands run) and **Decision** lines beneath it. The code spans above are the **literal text to paste**, `**` markers included.
- **A refuted unknown is a result, not a failure.** Sprint 38's prep refuted 32 % of its assumptions, Sprint 39's **63 %**. Record `❌ WRONG` plainly, state what it changes, and route it to the task or priority it affects.
- **When a verdict changes a classification, sweep on the changed SET** (S39 §7.6): grep `KNOWN_UNKNOWNS.md`, `PREP_PLAN.md` and every Sprint-40 prep doc for each affected model or symbol name, and fix every sentence that quoted the old state.
- **Update `PREP_PLAN.md`**: set the task **Status → ✅ COMPLETE (date)**, add a **Time Spent** line, fill the **Changes** and **Result** sections (replacing "*To be completed*"), check off **all** acceptance criteria `- [ ]` → `- [x]` — including "Unknowns … verified and updated in KNOWN_UNKNOWNS.md" — and prefix the task's Prep Task Overview row with ✅. **If a criterion cannot be met as written, amend it with the reason rather than ticking it** (Task 1 did this once).
- **Update `CHANGELOG.md`**: add an entry under `[Unreleased]` → `### Sprint 40 Prep` (newest first) summarising what was verified or produced, **including every refutation**.
- **Quality gate:** run **`make typecheck && make format && make lint && make test`** — **`make format` before `make lint`**, because `make lint` runs `black --check` (`Makefile` `lint:` target) and would stop the chain whenever formatting is needed — and confirm **all pass before committing** — **mandatory if any `*.py` changed** (`src/`, `tests/` or `scripts/`). Prep tasks are docs/analysis by default; if none changed, say so in the commit body as **"`src/` and `tests/` untouched — quality gate N/A"**. ⚠ State the waiver over that **stable scope**, never as "no `*.py` changed", and **re-derive it after committing and before every push**: `git diff main...HEAD --name-only | grep -c '\.py$'` (it reads commits, not the working tree). A review round that adds a script makes "no `*.py`" false while the stable-scope claim stays true.
- **Figures** (S39 §7.1–7.2): every figure carries the commit it was measured at; **re-measure, never re-quote**; record populations as **named lists with the predicate that produced them**, never as counts alone. Run `make check-doc-figures` before committing; if it flags a deliberately historical figure, mark the line `<!-- figures-ok: <reason> -->` rather than changing a correct figure.
- **Probes** (S39 §7.5): every probe, spy, mutant or scan **records its positive control** — evidence that it *can* fail. A pass without one is not evidence.
- **Run all GAMS from a scratch directory** (`mktemp -d`), never the repo root — GAMS writes `.lst`/`.log` next to its cwd, and some corpus sources `execute_unload` into it. **Never `git add -A` after a GAMS run.** Read results from GAMS's own lines (`MODEL STATUS`, `**** N ERROR(S)`), anchoring `^****` when grepping a `.lst`.
- **⚠ License hygiene:** **never paste, quote or commit any part of the license file or of a `.lst`/`.log` license header** — the `Licensee:` line, the license-ID lines and the node line identify the license. **Do not commit header excerpts at all, redacted or not** — a partial redaction leaves the ID and node lines. The automated leak scans (Task 3 *Verification*) are **limited** — they cannot catch an arbitrary partial quote without false positives — so **manually review `git diff main...HEAD` and every new file before each commit**, and record that the review was done. Record the *edition* only ("evaluation, valid to 2027-09-21" or "demo"), and, where a parser needs it, a non-identifying regex with its classification results.
- **Never write to the committed DB or goldens in prep.** Measurements that need the pipeline run in a **throwaway `git worktree`** or against a **scratch copy** of `data/gamslib/gamslib_status.json`; at commit time **both** `git diff --quiet main...HEAD -- data/` (nothing committed on the branch) **and** an empty `git status --porcelain --untracked-files=all -- data/` (nothing in the working tree, untracked included) must hold — `git diff HEAD` alone passes once a change is committed. (A licensed convexity run writing a convex status into the committed DB **grows the 142 corpus silently** — KNOWN_UNKNOWNS 3.3.)
- **The leak gate (`make check-goldens`) runs ALONE** — no concurrent pytest, GAMS batch or second gate; contention narrows its scope silently.
- **Run every verification command you write**, rather than only writing it.
- **Commit message:** `Complete Sprint 40 Prep Task <Z>: <Task Title>` — a single commit, with the verified unknowns (and their verdicts) and the produced artifacts listed in the body. **No `Co-Authored-By` line. No "Generated with Claude Code" line.** Check before every commit and every `gh pr create`: `grep -c "Co-Authored-By\|Generated with" <msgfile>` must print **0**.
- **Open a PR** with `gh pr create --base main` and push the branch. **The PR body is a pointer, not a mirror** (S39 §7.4): a two-to-four-line summary, the unknowns verified with their verdicts, and "see `PREP_PLAN.md` Task <Z> *Result*". If a review round changes the docs, regenerate the body from them at the end rather than patching it. **Then wait for reviewer comments.** Address each comment **on its own thread** via `gh api repos/jeffreyhorn/nlp2mcp/pulls/<N>/comments/<id>/replies -f body="..."` — **never** as a top-level PR comment; for a Copilot *suppressed* finding (no thread), anchor a new inline comment at the flagged line. After any round that changes `src/` or `scripts/`, grep the PR's own docs for every symbol they name and re-read those lines.
